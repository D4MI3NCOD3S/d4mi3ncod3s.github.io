CASE 03

알약 이미지 식별 Vision Pipeline

기간 2026.03 – 운영 중역할 단독 설계 · 구현 — 처음부터 끝까지 혼자 만든 시스템
Gemini VisionCLIPFAISSRedis jobFastAPI BackgroundTasks
ProblemBefore / AfterPipelineTrade-offContribution · MetricsRelated

Problem

각인 · 모양 · 색상으로 알약을 찾는 기능이 외부 식별 API에 의존했습니다. 비용 · 지연 · 장애가 외부에 묶여 있었고, 정확도를 우리가 개선할 방법이 없었습니다.

Approach

Vision LLM 단독으로는 각인 오독이 잦아, 규칙 기반 보정을 LLM 앞뒤에 배치했습니다. "10초"라는 지연 예산을 먼저 정하고 그 안에서 정확도를 최대화했습니다.

BEFORE

  • 외부 식별 API 호출
  • 비용 · 지연 · 장애가 외부에 종속
  • 단계별 튜닝 불가
  • 품질 측정 수단 없음
→내재화지연 예산

AFTER

  • 인프로세스 Vision Pipeline
  • 규칙 × LLM 결합 보정
  • 10초 예산 · 병렬화 · 모델 라우팅
  • Top-K 평가 하네스 CI 자동 실행

기술적 의사결정 · Trade-off

지연 예산을 먼저

정확도를 올릴수록 느려지므로 10초를 먼저 정하고 그 안에서 최적화. 약품별 병렬화, 조기 종료.

mini / full 모델 라우팅

쉬운 건 mini, 애매한 건 full. 비용과 정확도를 동시에 관리

재검증은 저신뢰에만

2-Pass 시각 재검증을 모든 요청에 걸지 않음.

불일치 감점

각인은 맞지만 색상이 다른 후보는 점수를 깎아 오탐을 억제.
